# Mid C++ Developer — Self‑Assessment Checklist

## Scoring Template

For each section, score yourself:
0 - No experience
1 - Basic understanding
2 - Can apply with guidance
3 - Independent and reliable
4 - Advanced; can work independently and mentor others
5 - Expert; Language Guru level



## C++ Skills

### Language Fundamentals
* [ ] I can explain and correctly use function templates and class templates
* [ ] I understand how type deduction works in template functions and can reason about common deduction cases
* [ ] I can apply CTAD and deduction guides in real code when they simplify usage
* [ ] I can use type traits in generic code and understand when they are useful
* [ ] I can write simple custom type traits for generic abstractions
* [ ] I know when to use `if constexpr` in template-heavy code and can apply it correctly
* [ ] I can write and use lambda expressions with captures and generic lambdas where appropriate
* [ ] I understand the common STL containers and can choose between them based on usage patterns
* [ ] I can use standard STL algorithms such as `find`, `sort`, and `transform` confidently
* [ ] I can write simple generic algorithms that work with iterators and range-like abstractions
* [ ] I understand namespace scope and argument-dependent lookup and can debug associated lookup issues

### Standard Library & Generic Programming
* [ ] I can select the right STL container for a given problem and explain trade-offs
* [ ] I understand iterator-based programming and can work with standard algorithms effectively
* [ ] I can write reusable generic code (algorithms, containers, and utilities)
* [ ] I can reason about the effect of template constraints and type traits on generic code design

## Software Engineering Skills

### Design & Architecture
* [ ] I know the core concepts behind common design patterns and can recognize them in codebases
* [ ] I can use UML class, sequence, and state diagrams to communicate design ideas
* [ ] I can reason about coupling and separation of concerns in medium-sized systems
* [ ] I can design SOLID code that is easier to maintain and extend without excessive complexity

### Memory & Quality
* [ ] I understand memory ownership and lifetime issues in C++ code
* [ ] I can use sanitizers and profilers to find memory leaks and invalid memory access
* [ ] I can diagnose common performance and correctness problems caused by bad memory usage
* [ ] I can write code that reduces accidental leaks and lifetime bugs

### Testing & Reliability
* [ ] I can write unit tests for non-trivial functionality
* [ ] I can use GoogleTest effectively for assertions, fixtures, and test organization
* [ ] I understand the value of automated tests in preventing regressions
* [ ] I can review code with an eye toward correctness, maintainability, and testability
